AbstractAdjunctGraph

com.phasmidsoftware.gryphon.adjunct.AbstractAdjunctGraph
See theAbstractAdjunctGraph companion object
abstract class AbstractAdjunctGraph[V, E, G <: AbstractAdjunctGraph[V, E, G]](vertexMap: VertexMap[V]) extends AbstractGraph[V], EdgeGraph[V, E]

Common base for the concrete edge graphs, DirectedGraph and UndirectedGraph.

G is the self type — the kind of graph this is. It exists so that unit, the single point at which a graph of this kind is built, is typed as that kind rather than as the base Graph[V].

That matters for more than tidiness. Until 1.8.1 UndirectedGraph.unit returned a DirectedGraph, and the compiler could not see it, because the declared return type erased the very distinction the two classes exist to carry. With G in place, the same mistake is a type error.

type EdgeT <: Edge[V, E]

The kind of edge this graph admits.

The kind of edge this graph admits.

An undirected graph admits UndirectedEdges and a directed one DirectedEdges. Before 1.8.0 addEdge took any Edge, so either graph would accept either kind — and the mismatch was not rejected but silently absorbed, leaving the graph inconsistent with itself: the adjacency was added, so degree counted it, while edges and M, which select by edge type, did not.

Making this a type member rather than narrowing addEdge's parameter in each subclass is what Scala allows: a parameter type may not be narrowed in an override, since that would break substitutability, but an abstract type member may be refined.

def adjacentEdges[E](v: V)(using random: Random = ...): Seq[Edge[V, E]]

Returns every edge adjacent to v, in adjacency order.

Returns every edge adjacent to v, in adjacency order.

Adjacencies that carry no edge — AdjacencyVertex, used where a connexion has no attribute — are dropped, so the result is the edges and only the edges. Nothing is filtered by discovery: this returns all of them, which is why it is no longer called undiscoveredEdges. That name described a design in which the caller tracked visited state; the traversal engine took that over and manages it internally through VisitedSet, but the name stayed behind and its body had long since degenerated to filteredAdjacencies(_ => true), which filters nothing. See issue #106.

For the adjacent vertices rather than the edges, use adjacentVertices, which is correct on undirected graphs as well — see the note there.

def dfs[E, J <: Appendable[E, J]](visitor: Visitor[V, E, J], order: DfsOrder = ...)(v: V)(using random: Random): Visitor[V, E, J]

Performs DFS from v, accumulating results into visitor.

Performs DFS from v, accumulating results into visitor.

If visitor is one of Visitor's came-from journals, note what that map holds: for each vertex, the vertex it was first seen from. For BFS that is also the vertex it was explored from, so the map is the BFS tree. For DFS the two differ — a vertex can be seen early from one neighbour and explored later from somewhere deeper — so the map is a discovery map and not the DFS tree. On a graph whose start vertex is adjacent to every other, it is a star where the DFS tree is a path. Walking it back still gives a genuine path to the start, but not the path the search took. See issue #144.

def unbuild[Z >: EdgeType]: EdgeList[V, E, Z]

Unbuilds this graph into a SerializableGraph — the inverse of what GraphBuilder does — from which serialize renders it in GraphParser's format. See #135.

Unbuilds this graph into a SerializableGraph — the inverse of what GraphBuilder does — from which serialize renders it in GraphParser's format. See #135.

The conversion is deliberately a separate step rather than this trait extending SerializableGraph. A graph is not a serializable description; it becomes one, and there are three descriptions it could become: EdgeList here, Triplets, and VertexPairList. Making EdgeGraph extend the trait would have conflated the model with its wire form and forced one of the three on every caller.

#135 described these as a 2x2 — attributed or not, against edge objects or raw tuples — with ProtoConnexions as the fourth. #137 found that ProtoConnexions and VertexPairList were one type written twice, so the attributeless, edge-object cell is in fact empty: there is no wrapper holding edge objects whose attributes are then discarded, and no reason to want one.

EdgeList is the natural target for a graph that has edges, and the conversion is only this line because EdgeList.triplets already carries it onward. A caller wanting one of the other two can convert from here.

Type parameters

Z

the edge-type parameter, a supertype of EdgeType so that EdgeList.triplets needs no cast.

Attributes

Returns

this graph as an EdgeList, the concrete type rather than SerializableGraph, so a caller keeps edges and pairs without having to cast back down.
